# 1. 用官方 QQ Bot 作为推送通道，而非 NapCat

- **Status**: Accepted
- **Context**:
  需要向 QQ 群推送比赛提醒，有两条路：非官方协议端（NapCat / Lagrange，基于 NTQQ，走 OneBot 11）或
  QQ 开放平台官方 Bot。非官方路线没有推送限制但需要真人小号扫码登录，社区普遍存在风控踢下线的问题；
  官方路线合规稳定，但个人主体只能把机器人加进自己是群主/管理员的群，且有主动消息频控
  （个人认证 60 qpm、单群每天上限 1000 条），并且群标识 `group_openid` 只能从事件中获取。
  本项目的推送量（一年几十场比赛、每场 2 条消息）远低于官方配额。
- **Decision**: 使用 QQ 开放平台官方 Bot。弃用 NapCat 路线。
- **Consequences**:
  - 更易：无封号风险，无需维护登录态与保活，不必准备小号，可长期无人值守。
  - 更易：只能服务"自己管理的群"，无法公开分享给陌生群。
  - 更难：必须实现一个接收事件的 webhook 端点（群注册与命令查询依赖它），并处理 Ed25519 签名验证。
  - 更难：必须处理 access_token 有效期（7200 秒）与消息格式（官方模板/markdown 约束）。
  - 若未来需要多群公开服务，需重新评估该决策（推送层应保持可替换）。
