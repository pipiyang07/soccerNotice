# 4. 主链路迁移到本地 Mac，Actions 降级为探测器

- **Status**: Accepted
- **Context**:
  ADR 0003 选择了懂球帝 + GitHub Actions。上线两天后，懂球帝开始对 Actions 运行器的云 IP 段
  返回 403（连 `www.dongqiudi.com/match` 网页本身都 403），而本机住宅 IP 用完全相同的请求
  一直返回 200。实测排除了 header、referer、cookie、请求频率等因素。
  同类站点普遍如此：SofaScore 对云 IP 弹人机验证，AiScore 按 TLS 指纹拦截（本地也拦），
  雷速接口要求客户端签名，网易彩票虽不拦但只收录竞彩赛事、没有国字号友谊赛。
  结论：免费中文数据源与云服务器 IP 无法共存，问题出在 IP 归属而非代码。
- **Decision**:
  采集与推送改由本机的 macOS launchd 定时任务执行（每小时第 20 分），
  使用住宅网络访问懂球帝；GitHub Actions 上的 collect 仅保留为"云端是否恢复可达"的探测器，
  不再写回任何数据；push 只保留手动触发，避免与本地读取不同 sent.json 造成重复推送。
  运行状态（fixtures / sent / health）只存在本地，仓库不再保存快照。
- **Consequences**:
  - 更易：住宅 IP 不在任何站点的机房黑名单内，采集恢复稳定，成本仍为零。
  - 更易：失败可退避（1h→3h→6h）并在连续失败时向群里告警，不需要人盯日志。
  - 更难：Mac 关机或睡眠期间不会推送；错过整点的执行会在唤醒后补跑一次，
    因此赛前提醒窗口从 ±1 小时放宽到 ±6 小时以保证不漏。
  - 更难：状态文件只在本机，换机器或重装系统需要迁移 `data/` 目录。
  - 更难：这套方案不再属于"纯 Cloud 运维"，依赖一台常开设备的可用性。
